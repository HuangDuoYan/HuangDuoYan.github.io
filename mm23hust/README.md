# 顶会论文方法论解剖室

一份基于 **Vue 3** 的交互式图文长页，用于回答 `figure_out_needed.md` 提出的问题：
**顶会论文是如何从问题一步步推导出具体技术设计的。**

被解剖的论文：

> Yuxin Kong, Peng Yang, Yan Cheng.
> *Edge-Assisted On-Device Model Update for Video Analytics in Adverse Environments.*
> ACM MM '23, pp. 9051–9060. DOI 10.1145/3581783.3612585

## 打开方式

直接双击 `index.html` 即可（`file://` 亦可运行，无需构建、无需联网）。
若需要通过 HTTP 打开：

```bash
python3 -m http.server 8000     # 然后访问 http://127.0.0.1:8000/
```

## 内容结构

页面按 `figure_out_needed.md` 的六个维度组织，并补了一节反向审阅和一个图库：

| 章节 | 对应要求 | 主要交互 |
| --- | --- | --- |
| 封面 | 论文名片 + 主矛盾 | 三个角色出场对白、实验参数展开 |
| ① 问题抽象 | Problem Abstraction | **矛盾张力图**（5 条系统级张力，可点选）、已有方法失效对照表（按张力筛选）、**恶劣环境滑块演示**（拖动 → 检测框消失、F1 下降） |
| ② 技术推导链 | Technique Derivation Chain | **10 层递归推导阶梯**：问题 → naive → 为何失败 → 新约束 → 新技术 → 新问题；支持逐层展开 / 自动推导播放；内嵌 3 个模拟器 |
| ③ 技术结构映射 | Structure Mapping | 11 张**可翻面卡片**（正面=本文机制与抽象，背面=经典技术结构与"为何适配"）、**两条离线拟合曲线**交互探索 |
| ④ 隐藏约束 | Hidden Constraints | 13 项约束的**视角切换**（普通论文 / 本文 / 并排对比）、延迟四段分解图（占比↔秒数切换）、量化结论墙、首次更新双轴对比 |
| ⑤ 设计模式 | Design Pattern | 12 条模式清单 + 每条的"本文如何用 / 还能迁移到哪" |
| ⑥ 我该学到什么 | Most Important | 8 条思维动作（每条附可操作建议）+ **八问推导器**（填入你自己的问题，生成属于你的检查清单） |
| ⑦ 反向审阅 | 额外补充 | 6 个可攻击点及其"下一步" |
| ⑧ 论文图库 | 额外补充 | 14 张原图（Fig.2 拆为 a/b）+ 每张的"方法论读法"，可点击放大 |

### 三个可交互模拟器

它们不是装饰，而是把论文三个模块的判据真正跑起来：

1. **Key Frame Extractor（Algorithm 1）** — 拖 β 与带宽，看两步级联如何选帧；
   一键把"先过滤后算帧差"反转成"先算帧差后过滤"，直接看到端侧像素级计算量从 15 帧涨到 24 帧。
2. **Trigger Controller** — 实现 `μ_{i<j} − σ_{i<j} > a_j` 的控制图；
   四个场景已校核（γ ∈ [0.2, 0.98] 全区间结论稳定）：
   *高抖动* → 本文不触发 / JIT 固定阈值误报；*缓降* → 本文已触发 / JIT 仍在等待。
3. **Retraining Manager（U = A − ηT，Algorithm 2）** — 用论文原式
   `A = 0.9194 − 0.3218·e^(−9.9692·e·n)` 预测精度、按四段结构建模延迟；
   可运行带 Metropolis 准则的扰动搜索，并与穷举最优对照；τ₀ = 60s 越界会实时报警。

### 卡通角色

三个纯 SVG 角色，各自有 `疑惑 / 思考 / 感悟` 三种情绪形态（问号浮动、思考气泡、灯泡闪烁），
旁边的气泡带 SVG 尾巴与打字机效果；每节末尾的"角色旁白"按 **疑惑 → 思考 → 感悟** 推进：

- **小惑**（研究生）— 提出朴素疑问，扮演读者的第一反应
- **老衍**（方法论导师）— 做推导，把疑问翻译成约束
- **阿悟**（端侧摄像头，当事人）— 给出感悟，负责收口

右下角还有一个常驻的悬浮小助手，会轮换阅读提示。

## 数字的出处（重要）

页面上每处数据都标注了来源，三类严格区分：

- **论文原文** — 取自正文论断或图内标注。例如 Fig.1 的 F1（0.857/0.800 → 0.667/0.600）、
  Fig.8 的 F1 与响应时间（Ours 0.868 / 52s，Ekya 0.790 / 84s，JIT 0.723 / 67s，NR 0.785→0.619）、
  延迟四段占比（7.8% / 5.2% / 86.2% / 0.8%）、Ekya profiler 占 27%（≈25s）、
  较 Ekya 削减 52.7% 重训时间、精度提升上限 24%（对 NR）与 12%（对 Ekya）、
  配置搜索 20ms、拟合式 `A(e·n)` 与 `R² = 0.979`、以及全部超参（β=0.4、W=10s、τ₀=60s 等）。
- **反推示意** — 由论文给出的百分比换算的秒数（分解图的绝对秒数）。
- **演示取值** — 仅供交互模拟：`t(m)` 斜率、单帧数据量 `d₀`、标注耗时 `t₀`、模型大小 `M₀`、
  窗口抽样 24 帧、JIT 阈值与 Ekya 周期。公式形式取自论文，数值非原文。

论文未给出数值的图（如 Fig.9 各方案平均 F1）**没有编造柱状图**，直接展示原图。

## 图片是怎么来的

`work/crop_figs.py` 不靠手工试错：

1. 先用 `pdftotext -bbox` 定位每条图题的坐标，据此给出一个"宽松"的裁切带（避开页眉与正文列）；
2. 用 `pdftoppm` 把该带渲染成 PPM，在纯 Python 里算出真正的**非白像素外接框**，把裁切框收紧；
3. 对并排子图（Fig.2/4-5/6-7/11-12）再做一次**列向空白间隙检测**自动劈分；
4. 最后以 260 dpi 输出 PNG。

复现：

```bash
python3 work/crop_figs.py        # 需要 poppler-utils 提供 pdftotext / pdftoppm
```
